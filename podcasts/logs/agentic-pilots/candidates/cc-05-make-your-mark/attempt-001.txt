Now let's talk about PR descriptions. A strong PR description answers key questions for your reviewer. Why does this change exist? What problem does it solve or what goal does it advance? What is the scope? Which files changed and how big is the change? How was it tested? Did you verify the change works? What should the reviewer pay attention to? Are there tricky parts, trade-offs, or areas where you want a second opinion?

[JAMIE]
What about the pattern for closing issues?

[ALEX]
GitHub recognizes special keywords in PR descriptions that automatically close linked issues when the PR merges. Include the keyword Closes followed by the issue number. For example, Closes #5 will close issue 5 when your PR merges. You do not need to close issues by hand.

[ALEX]
One of the most effective patterns is showing the state before your change and the state after. This gives the reviewer an instant mental model without reading the diff line by line. The workshop is closer to rehearsal than lecture. You hear the move, try the move, and then check what changed.

Common mistakes to avoid: No context about what file or what was wrong with it. No linked issue. No explanation of the change. These mistakes force a reviewer to open the diff, figure out which file changed, read every line, and guess at intent. Instead, give them the context they need.

[JAMIE]
Can you show a side-by-side?

[ALEX]
A bad PR description has no context: "Fixed TODO." That is it. A reviewer has to do all the work. A good PR description says: "Fixed welcome.md TODO in the Who Can Contribute section. I added a paragraph explaining that students, maintainers, and community members can all contribute. Closes #2." Now the reviewer knows exactly what changed and why.

[ALEX]
Use Markdown headings in your description so reviewers can press H to jump between sections. Use Markdown headings like Summary, Changes, Related Issues, Testing. Type Closes followed by the issue number to auto-close the linked issue on merge. Preview your Markdown before submitting. Press Ctrl+Shift+P in the description text area to toggle between Write and Preview modes. Keep bullet points short so the description is scannable. When including screenshots, add alt text.
