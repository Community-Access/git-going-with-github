## What Is a GitHub Issue?
An issue is a unit of work: bug report, feature request, question, or task. It has anatomy: title, body in Markdown, labels, assignees, milestone, state (open or closed), and a timeline of activity.

## Filing a New Issue:
### Navigating to New Issue starts from the Issues tab.
### Filling Out the Issue Form means clarity over length.
#### Title field: specific and actionable.
#### Description / Body field: enough detail to reproduce and triage.

[ALEX]
Use this template structure when relevant:
## What happened
## What I expected
## How to reproduce
## Environment
## Additional context

[ALEX]
Then set metadata: assign yourself or a teammate, add or remove labels, pick a milestone, and submit.
### Assigning labels from the sidebar keeps triage consistent.
### Submitting the issue creates the canonical discussion thread.
### Learning Cards: Filing a New Issue reinforces quality checks.
### Tool Cards: File a New Issue gives quick operational steps.

[JAMIE]
And lifecycle management?

[ALEX]
Closing means the work is resolved, duplicate, or no longer needed. Reopening is valid when new evidence shows the problem remains.

[ALEX]
Issues and pull requests are tightly connected: PRs can reference issues, and closing keywords in PR descriptions can auto-close linked issues when merged.

## Cross-Referencing Issues:
### Closing keywords in PR descriptions or issue comments can resolve linked issues.
### Mentioning another issue in a comment creates traceable relationships.
### Cross-repo references work with owner/repo#number format.
