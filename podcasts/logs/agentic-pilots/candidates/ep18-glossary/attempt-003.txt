[ALEX]
Part 1 is the building blocks.

[ALEX]
Repository, or repo, is the container for a project. It holds the files, folders, history, and everything Git knows about the work.

[JAMIE]
That one matters because it is where the whole story lives.

[ALEX]
Right. Organization, or org, is a GitHub group account. Teams often place open source projects there instead of under a personal account.

[ALEX]
A fork is your own copy of someone else’s repository in your GitHub account. Pronunciation note: fork means the copy of the repo, not a literal fork in a road.

[JAMIE]
So if I fork a project, I get my own version to work from.

[ALEX]
Exactly. Remote means a repository hosted somewhere else, usually on GitHub. Your local repo can point to more than one remote.

[ALEX]
If you want to see your remotes, a common command is `git remote -v`. If you want to add one, you might use `git remote add upstream <url>`. Read commands as examples first, not as magic words.

[JAMIE]
And origin?

[ALEX]
Origin is the default name Git gives to the remote you cloned from. Most of the time, origin points to your fork. Upstream is the original project you forked from.

[ALEX]
`.gitignore` is a file in the root of the repo that tells Git what not to track. Use it for build files, temporary files, secret files, and editor-specific clutter.

[JAMIE]
So it helps keep the repository clean.

[ALEX]
Yes. Example entries might include `dist/`, `node_modules/`, `.env`, `.vscode/`, or `.idea/`. Important detail: `.gitignore` only affects files Git has not already started tracking.

[PAUSE]

[ALEX]
Clone means copying a repository from GitHub down to your computer so you can work on it locally.

[ALEX]
Branch is a separate line of development inside a repository. Most work happens on branches, not directly on the stable main line.

[JAMIE]
What are the common branch names people should recognize?

[ALEX]
`main` is usually the primary branch. `develop` is sometimes used as an integration branch. `feature/my-change` is a common feature branch pattern. `fix/button-label` is a common bugfix pattern. `docs/update-readme` is for documentation work.

[ALEX]
Commit is a saved snapshot of your changes at a moment in time. A good commit message says what changed, not just that something changed.

[JAMIE]
And the diff?

[ALEX]
A diff shows the difference between two versions of a file. Added lines usually show up as green or with a plus sign. Deleted lines show the opposite.

[PAUSE]

[JAMIE]
Move into collaboration.

[ALEX]
Issue is a discussion item in a GitHub repository. People use issues for bugs, features, questions, and ideas. It usually has a number, a title, a body, labels, comments, and sometimes assignees or milestones.

[ALEX]
Pull request, or PR, is a proposal to merge changes from one branch into another. You use it to say, “Here is the work, please review it.”

[JAMIE]
That is the handoff point.

[ALEX]
Code review is when collaborators read the pull request and give feedback before merge. Good reviews are specific, kind, and useful.

[ALEX]
Merge is combining changes from one branch into another. When a PR is approved, someone with permission or responsibility may merge it.

[JAMIE]
What about the nasty case?

[ALEX]
Merge conflict happens when two branches change the same part of the same file in incompatible ways. Git stops and asks a human to decide.

[ALEX]
Upstream, in collaboration language, is the original repository a fork came from. When the original project changes, you may sync your fork with upstream.

[JAMIE]
And labels, milestones, and projects?

[ALEX]
Label is a tag you add to an issue or PR to categorize it. Milestone groups work toward a shared target. Project, in GitHub Projects, is a planning board for organizing work across issues and PRs.

[PAUSE]

[ALEX]
Part 3 is people and roles.

[ALEX]
Maintainer is the person or team that keeps the project healthy and makes final calls.

[JAMIE]
Contributor is the person doing the work.

[ALEX]
Exactly. Contributor is anyone who adds code, docs, tests, or fixes.

[ALEX]
Triage is the process of sorting and prioritizing incoming issues or PRs. Collaborator is someone with permission to help manage the repository.

[PAUSE]

[JAMIE]
What about the shorthand people hear in chats and docs?

[ALEX]
That is Part 4: common abbreviations and slang. Repo means repository. Org means organization. PR means pull request. CI means continuous integration. CD often means continuous delivery or continuous deployment. Dev usually means developer or development. SHA is the commit hash, like a fingerprint. Pronunciation note: SHA is usually said “sha,” and CI/CD is often said as separate letters.

[PAUSE]

[ALEX]
Part 5 is the technical GitHub concepts.

[ALEX]
HEAD is the commit or branch you are currently on. It is where Git says, “this is the point I’m looking at right now.”

[JAMIE]
Detached HEAD sounds scary.

[ALEX]
Detached HEAD means HEAD points to a commit instead of a branch. It can happen when you check out a specific commit or tag. It is not a disaster, but it means new commits are not attached to a named branch unless you create one.

[ALEX]
Stash is a temporary place to save unfinished changes so you can switch tasks without committing them.

[JAMIE]
What is the usual stash workflow?

[ALEX]
Save the work, switch branches, do the urgent task, then bring the stash back later. You might hear commands like `git stash`, `git stash list`, and `git stash pop`.

[ALEX]
Rebase is a way to move or replay commits onto a different base commit. Merge and rebase can both combine work, but they do it differently.

[JAMIE]
When should someone use rebase?

[ALEX]
Use rebase when you want a cleaner linear history and you understand the branch is yours or the team agrees on that workflow. Do not rebase shared history casually.

[ALEX]
Cherry-pick means taking one specific commit and applying it somewhere else. It is useful when you want a single fix without the rest of the branch.

[JAMIE]
And fetch versus pull?

[ALEX]
Fetch downloads new information from a remote without changing your working branch. Pull does a fetch and then brings those changes into your branch.

[ALEX]
Force push is pushing changes in a way that overwrites remote history. It can be necessary after a rebase, but it is risky.

[JAMIE]
So when is it okay?

[ALEX]
Only when you know the impact and your team expects it. Never use force push on shared work unless that is part of the plan. A safer option is `--force-with-lease`.

[ALEX]
SHA or hash is the unique identifier for a commit. It looks like a long string of letters and numbers, and GitHub often shows a shorter version in the UI.

[PAUSE]

[JAMIE]
Now bring it back to GitHub workflow terms.

[ALEX]
A review can be draft, meaning it is still a work in progress. Status checks are automated results from tests or workflows that must pass before merge in many projects.

[JAMIE]
So a PR is not just code, it is a conversation plus evidence.

[ALEX]
Exactly. And the workflow terms fit together: branch, commit, push, pull, clone, fork, issue, PR, review, merge conflict, status check, merge.

[PAUSE]

[ALEX]
Now the accessibility terms.

[ALEX]
Screen reader is software that reads page content aloud or sends it to a Braille display. It helps blind and low-vision users navigate content.

[JAMIE]
What is a landmark?

[ALEX]
A landmark is a major page region, like navigation, main content, or search. Landmarks help screen reader users jump around efficiently.

[ALEX]
A heading gives structure to the page. It lets people scan, jump, and understand the hierarchy of content.

[JAMIE]
And ARIA?

[ALEX]
ARIA stands for Accessible Rich Internet Applications. It adds accessibility information when native HTML is not enough, but it should be used carefully and only when needed.

[ALEX]
Focus is where keyboard interaction currently lives. Tab order is the sequence focus moves through the page when someone presses Tab.

[JAMIE]
So if tab order is broken, keyboard users feel it immediately.

[ALEX]
Yes. That is why logical focus order matters so much.

[PAUSE]

[ALEX]
Now the agent terms.

[ALEX]
Copilot is GitHub’s AI assistant. It can help draft code, docs, commit messages, and other text.

[JAMIE]
And an agent?

[ALEX]
An agent is a more autonomous assistant that can take actions on your behalf inside a workflow.

[ALEX]
A slash command is a typed command that starts with `/`, usually inside a chat or agent interface. It triggers a specific action.

[JAMIE]
So a prompt is the instruction you give the model.

[ALEX]
Right. And an instruction file is a file that stores guidance for the agent or assistant so it can follow consistent project rules.

[PAUSE]
