[ALEX]
Now Labels.

[ALEX]
What are labels? Color-coded tags used to categorize issues and pull requests by type, priority, status, or area.

[JAMIE]
What standard labels do people usually see?

[ALEX]
Common defaults include bug, enhancement, documentation, question, duplicate, help wanted, good first issue, and wontfix, though repos can customize.

[JAMIE]
Where do I find them?

[ALEX]
Navigating to the Labels page: open the repository, go to Issues, then select Labels near the filter controls.

[ALEX]
Applying a label to an issue or PR: open the item, use the Labels control in the right sidebar, select one or more labels, and save.

[JAMIE]
Give me a tool-card style CLI version.

[ALEX]
Apply a label with gh:
gh issue edit 42 --add-label "bug"
gh pr edit 15 --add-label "documentation"
gh issue edit 42 --remove-label "needs triage"

[ALEX]
Filtering issues by label can be done in the Issues search bar with queries like:
is:open label:bug
is:issue label:"good first issue"

[ALEX]
CLI filter example:
gh issue list --label "accessibility" --state open

[JAMIE]
How do we create a new label correctly?

[ALEX]
Creating a new label requires three fields: name, description, and color. In UI, use New label on the Labels page. In CLI:
gh label create "accessibility" --description "Accessibility-related work" --color "0075ca"

[ALEX]
Learning cards for labels: use labels to answer what kind of work this is, who should notice it, and how it should be filtered later.

[PAUSE]

[ALEX]
Next: Milestones.

[ALEX]
What are milestones? They group related issues toward a release, deadline, or goal.

[JAMIE]
How do I navigate milestones?

[ALEX]
Go to Issues, then Milestones. Reading a milestone means checking scope, due date, open and closed counts, and completion progress bar.

[ALEX]
Opening a milestone: select an existing one to review work status and linked issues.

[ALEX]
Adding an issue to a milestone: open the issue and choose the milestone in the sidebar.

[JAMIE]
And creating one from scratch?

[ALEX]
Creating a milestone includes title, optional description, and due date. That due date gives planning pressure and progress visibility.

[ALEX]
CLI milestone management examples:
gh api repos/{owner}/{repo}/milestones -f title="v1.0" -f due_on="2026-06-30T00:00:00Z"
gh issue edit 42 --milestone "v1.0"

[ALEX]
Learning cards for milestones: use them to answer what this work contributes to and whether release goals are on track.

[PAUSE]

[ALEX]
Cross-References section.

[ALEX]
Types of cross-references include issue-to-issue, PR-to-issue, commit-to-issue, and project item links.

[JAMIE]
How do we type a cross-reference?

[ALEX]
Use shorthand like #123 in comments, issues, or PR descriptions. GitHub auto-links when it can resolve the reference.

[ALEX]
When the "Closes" keyword fires: it closes the referenced issue when the linked PR is merged into the default branch, not when the comment is posted.

[ALEX]
Learning cards for cross-references: link related work early so context is discoverable in timelines and audits.

[PAUSE]

[ALEX]
Now GitHub Projects, the new project boards.

[ALEX]
What is a GitHub Project? A flexible planning space that can track issues and PRs across one or many repositories.

[JAMIE]
How do learners find a project?

[ALEX]
From the repository Projects tab or from the organization-level Projects page, depending on where it was created.

[ALEX]
Navigating a project in Table view: scan rows as work items and columns as fields like Status, Priority, Assignee, Labels, and Milestone.

[ALEX]
What is announced per row in table terms: title first, then key metadata fields that define workflow state.

[ALEX]
Navigating a project in Board view: work appears as cards grouped in columns such as Todo, In Progress, and Done.

[ALEX]
Roadmap view overview: timeline-style view for date-based planning, useful for milestones and longer delivery windows.

[JAMIE]
How do you add an issue to a project?

[ALEX]
From the issue sidebar Projects field, or inside the project with Add item and search by issue number or title.

[ALEX]
Learning cards for projects: choose the view that matches the question. Board for flow, table for detail, roadmap for time.
