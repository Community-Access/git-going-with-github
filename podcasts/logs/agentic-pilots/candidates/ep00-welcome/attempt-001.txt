How does the course structure work in practice?

[ALEX]
Think in two layers: **Live Agenda and Self-Paced Curriculum**. Live sessions cover the minimum path to make a real contribution; the full chapters support prep, catch-up, remote participation, and post-event continuation.

[ALEX]
Then the two-day split: **Day 1 - GitHub Foundations (Browser)** and **Day 2 - VS Code + Accessibility Agents (Desktop)**.

[JAMIE]
What is the Day 1 promise?

[ALEX]
Keyboard and screen-reader friendly GitHub basics in the browser: repository navigation, issues, branches, commits, and your first pull request.

[JAMIE]
And Day 2?

[ALEX]
VS Code plus agents. You apply the same workflow with more power, including a 55-agent accessibility system across 3 teams: one team finds issues, one proposes and applies fixes, and one validates and reports results.

[PAUSE]

[JAMIE]
Where does the learning philosophy show up?

[ALEX]
In **The Journey Arc**: manual skill first, then automation. If you understand the human workflow, agent output is teachable and trustworthy.

[ALEX]
High-level preview terms stay simple: a **repository** is your project home, an **issue** tracks work, a **pull request** proposes changes, and a **merge** brings approved changes into the main line.
