Work.md

Consolidated walkthrough of the 21 issue-based challenges in the Learning Room. Use this as a single working file while you move through the challenge issues in order.

Core challenges

1. Find Your Way Around

  • Chapter links: Ch02, Ch03, Ch04
  • Goal: Explore the repository, find the Issues tab, and locate key files.
  • Do:
    • Find the Code tab and count files in the repository root.
    • Open Issues and find an open issue.
    • Read the first paragraph of docs/welcome.md.
    • Find the repository description and the README.
  • Evidence: Short notes about what you found in each step.

2. File Your First Issue

  • Chapter link: Ch05
  • Goal: Find a TODO in docs/welcome.md and turn it into a clear issue.
  • Do:
    • Search docs/welcome.md for TODO.
    • Open a new issue with a specific title.
    • Explain what needs to change, where it is, and why it matters.
  • Evidence: Link to the issue you created and explain the TODO.

3. Join the Conversation

  • Chapter links: Ch05, Ch08
  • Goal: Practice comments, @mentions, and reactions in an issue thread.
  • Do:
    • Find the peer-simulation issue or a buddy issue.
    • Leave a useful comment with an @mention.
    • Add a reaction or another helpful response.
  • Evidence: Link to your comment and describe why it was useful.

4. Branch Out

  • Chapter links: Ch06, Ch04
  • Goal: Create a safe working branch for your Day 1 changes.
  • Do:
    • Find the branch selector.
    • Create learn/YOUR-USERNAME from main.
    • Confirm you are on the new branch.
  • Evidence: Branch name and how you confirmed it.

5. Make Your Mark

  • Chapter links: Ch06, Ch04
  • Goal: Edit docs/welcome.md and commit the change clearly.
  • Do:
    • Switch to learn/YOUR-USERNAME.
    • Replace the TODO in docs/welcome.md.
    • Commit with a meaningful message.
  • Evidence: Commit message and edited file.

6. Open Your First Pull Request

  • Chapter link: Ch06
  • Goal: Open a PR from your branch to main.
  • Do:
    • Create a pull request from learn/YOUR-USERNAME to main.
    • Include Closes #XX in the description.
    • Write a clear title and summary.
  • Evidence: PR link and the issue it closes.

7. Survive a Merge Conflict

  • Chapter link: Ch07
  • Goal: Resolve a merge conflict safely and cleanly.
  • Do:
    • Wait for the conflict to be triggered.
    • Read the conflict markers carefully.
    • Keep the right content and delete all marker lines.
    • Commit the resolution.
  • Evidence: What you kept and why.

8. The Culture Layer

  • Chapter links: Ch08, Ch09
  • Goal: Reflect on open source culture and practice issue triage.
  • Do:
    • Answer the reflection prompt.
    • Add or recommend a label if the issue asks for triage.
    • Explain your communication or triage choice.
  • Evidence: Three concrete collaboration behaviors you will use.

9. Merge Day

  • Chapter links: Ch06, Ch10
  • Goal: Merge your Day 1 PR and confirm the issue closes.
  • Do:
    • Verify the PR is ready.
    • Merge it or have a facilitator merge it.
    • Confirm the change landed on main.
    • Confirm the linked issue closed automatically.
  • Evidence: Merged PR link and closed issue number.

10. Go Local

  • Chapter links: Ch13, Ch14
  • Goal: Clone the repo locally, work on a branch, commit, and push.
  • Do:
    • Clone the Learning Room repository.
    • Create fix/YOUR-USERNAME.
    • Edit a file in docs/.
    • Commit and push the branch to GitHub.
  • Evidence: Branch name and how you confirmed the push.

11. Open a Day 2 PR

  • Chapter links: Ch14, Ch15
  • Goal: Open a PR from a locally pushed branch.
  • Do:
    • Open a PR from fix/YOUR-USERNAME to main.
    • Write a clear title and description.
    • Confirm the branch-to-main workflow feels familiar.
  • Evidence: PR link and what changed.

12. Review Like a Pro

  • Chapter link: Ch15
  • Goal: Give thoughtful code review feedback.
  • Do:
    • Open a buddy PR or peer-simulation PR.
    • Read the diff in Files changed.
    • Leave at least two inline comments.
    • Submit a review verdict.
  • Evidence: Review link or where the comments were left.

13. AI as Your Copilot

  • Chapter link: Ch16
  • Goal: Use Copilot as a collaborator, then judge its suggestions.
  • Do:
    • Ask Copilot to improve a documentation file.
    • Accept, modify, or reject suggestions thoughtfully.
    • Keep notes on what changed and why.
  • Evidence: Prompt used and one suggestion you changed or rejected.

14. Template Remix

  • Chapter link: Ch17
  • Goal: Create an accessible YAML issue template.
  • Do:
    • Study docs/samples/challenge-14-registration-remix-example.yml.
    • Create a new template in .github/ISSUE_TEMPLATE/.
    • Include name, description, title, and at least one form field.
    • Commit and push the template.
  • Evidence: Link to the template or PR.

15. Meet the Agents

  • Chapter link: Ch19
  • Goal: Inspect real accessibility agents before building one.
  • Do:
    • Browse the accessibility-agents repository.
    • Find at least three agents.
    • Run or inspect one agent.
    • Read one .agent.md file and identify its purpose and guardrails.
  • Evidence: Agent names and one guardrail that stood out.

16. Build Your Agent (Capstone)

  • Chapter links: Ch18, Ch20
  • Goal: Fork, write, and submit an agent-focused contribution.
  • Do:
    • Fork the accessibility-agents repository.
    • Create agents/YOUR-AGENT-NAME.agent.md.
    • Include valid YAML frontmatter, responsibilities, and guardrails.
    • Open a cross-fork PR.
    • Review a peer or facilitator-seeded agent.
  • Evidence: Fork URL, PR URL, agent name, purpose, and guardrails.

Bonus challenges

Bonus A. Improve an Existing Agent

  • Goal: Make one existing agent better and explain why.
  • Do:
    • Choose an agent in accessibility-agents.
    • Identify one focused improvement.
    • Open a PR with your change and rationale.
  • Evidence: Agent name, change made, why it helped, PR link.

Bonus B. Document Your Journey

  • Goal: Write a structured reflection about the workshop.
  • Do:
    • Create reflections/YOUR-USERNAME.md.
    • Include before, during, after, what you built, and advice for future students.
    • Commit and open a PR.
  • Evidence: Reflection link or PR link.

Bonus C. Create a Group Challenge

  • Goal: Design a collaborative challenge for 3-5 students.
  • Do:
    • Create docs/group-challenges/YOUR-USERNAME-challenge.md.
    • Include title, goal, team size, time estimate, instructions, success criteria, and accessibility note.
    • Commit and open a PR.
  • Evidence: Challenge description and file URL.

Bonus D. Notification Mastery

  • Goal: Configure GitHub notifications for productive inbox management.
  • Do:
    • Review email, web, watching, routing, and mobile notification settings.
    • Explain how you will know when review is needed.
    • Explain how you will avoid notification overload.
  • Evidence: Notification strategy and settings summary.

Bonus E. Explore Git History Visually

  • Goal: Use GitHub Desktop or GitHub.com to study repository history.
  • Do:
    • Open the repository history or network graph.
    • Look for branches, merges, and your own commits.
    • Identify the oldest commit and a merge commit.
  • Evidence: Tool used, branch count, and one surprising history detail.

  6. Bonus A-E if you want extra practice
